# 全量照明控制节点接入

2026-09-11：当前程序实例化 **1,690 个独立控制节点**，管理 **8,363 盏灯具**，不再运行仅10个代表节点的模式。

## 教室如何控制

- 主楼10层，每层10间教室，共100个教室节点。
- 每个教室节点控制本教室12盏灯；当前功率估算为12×36W＝432W。
- 第1间保留历史编号 `CL-N01`；第2至第100间为 `CL-MAIN-ROOM-0002` 至 `CL-MAIN-ROOM-0100`。
- 主楼第100间在页面中显示为“主楼教室 · 1栋10层10号”，可以单独开关、调光、注入故障。
- 每个节点均有独立 `zone_id`、照度/人员传感器编号、采样随机序列、控制滞回状态及故障状态。
- 教一至教四另外有192个教室控制节点；走廊、楼梯、灯杆及其他分区也逐个展开。

## 页面使用

1. 系统总览确认“已接入控制节点”为1690。
2. 区域与设备页查看楼层、回路灯具数和额定功率，下载完整数量清单。
3. 远程控制页先筛选规划片区，再在节点框搜索楼层名称或节点编号，执行单节点操作。
4. 智能照明页可以选择任意控制节点，查看独立的Lux、亮度和功率曲线。
5. 能耗分析逐一计算全部1690个回路，全天5分钟采样共486720点；相同模型和日期的结果在页面间缓存，避免重复运算。
6. 实验与测试页下方的“全部控制节点联合仿真”可运行5分钟、1小时或24小时。全部节点经过环境、照明、三网关链路及故障检测；界面只展示最后200条采样，汇总统计覆盖全部记录。该实验使用独立状态，不覆盖当前人工操作。

## 数据库与兼容性

`scripts/migrate_deployment.py` 先备份旧数据库，再补齐所有设备。旧CL-N01～CL-N10成为相应类型的第一条实际回路，而不是额外增加的代表节点。升级更新设备定义和额定功率，保留手动亮度、模式、告警和运维记录；不清空历史数据。

备份在 `database/backups/`。正常启动也会执行幂等建表和增量补齐。应用检测到新的部署版本时会扩展会话中的设备清单。

## 计算与边界

数量依据见 [照明清单](lighting_quantity_plan.md)。`deployment.py` 基于该清单生成每个设备，室内常规灯按36W、走廊楼梯入口18W、路灯120W、体育高杆单灯200W及其他体育灯100W估算。位置、楼层及单灯功率仍是设计假设。

在2026-09-09的全量自动照明实验中，传统基线为4404.960 kWh，智能方案为2852.859487 kWh，估算节能率35.24%。基线仍为07:00–22:00全亮。旧PPT中的17.070/8.349 kWh及51.09%属于旧10节点版本，不能作为当前结果。

三网关模型会计算全部节点的链路，但未模拟完整LoRaWAN MAC、碰撞或接入容量；1690节点的软件接入不代表三台真实网关已通过全校部署验收。
